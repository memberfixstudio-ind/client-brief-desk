# Contributing

Start with a real workflow problem. Describe the steps, expected result, WordPress/PHP versions and whether the issue occurs with a standard theme. Use fictional data; do not post client answers or credentials.

Use the [validation guide](docs/VALIDATION.md) to run the real WordPress tests on a disposable installation. Add a focused regression check for a behavioral change. Preserve account isolation, private notes, transaction boundaries and conflict recovery. Check the staff and client interfaces at desktop and mobile widths when changing UI.

There is no build step or production package dependency. Keep PHP and JavaScript strings translatable. Update CHANGELOG.md for user-visible changes. Submit a pull request with the problem, resulting behavior and checks actually run.

Report security issues privately through [Security Advisories](https://github.com/memberfixstudio-ind/client-brief-desk/security/advisories/new).
